# Нативное Rust-приложение

## Статус нативного GUI

Нативный Windows GUI находится в `crates/factory-atlas-app/`. Он использует eframe/egui с `winit` и OpenGL (`glow`), а операции над проектом и формат `.factoryatlas` — из `factory-atlas-core`.

На первом этапе пользователь может:

- начать с полностью пустого проекта;
- создать предмет или жидкость, задав собственный ID и RU/EN названия;
- добавить узлы источника, цели и заметки;
- указать темп источника/цели и связать узлы только при совпадении ресурса и единиц;
- открыть, сохранить и повторно открыть существующий формат `.factoryatlas` (в том числе мигрировать v1 через общий парсер core).

### Рабочее пространство

Нативное окно включает тёмную графитовую и светлую темы, левую навигацию и каталог проекта, центральный граф, инспектор выбранного узла и панель расчёта. Размеры каталога/инспектора и высота панели расчёта регулируются мышью. Узлы можно выбирать и перетаскивать; граф масштабируется Ctrl+колесом, перемещается средней кнопкой мыши. Типы потоков предметов и жидкостей имеют отдельные цвета, побочные продукты отмечаются отдельно.

Решатель и индексатор ассетов используют общий worker pool из двух потоков. Индексация моделей/blockstates/текстур показывает счётчик обработанных файлов, может быть отменена и не блокирует UI. Индекс хранится в локальной папке данных приложения и повторно используется для выбранного корня; оригинальные файлы не копируются. Предпросмотр PNG декодируется в фоне при выборе, ограничен размером исходного файла 16 MiB, разрешением 16 MP и четырьмя миниатюрами в кэше.

Доступны экраны графа, пользовательских ресурсов и локальной библиотеки визуальных ассетов. Можно выбрать texture pack или каталог `assets`, искать по ID/названию, просматривать PNG как 2D-текстуру и вручную привязать её к уже существующему пользовательскому ресурсу. Привязка записывается в `.factoryatlas`; библиотека не создаёт игровые ресурсы и рецепты. В каталоге ресурсов показывается миниатюра привязанного оригинала. Для доступа после перезапуска путь библиотеки сохраняется в пользовательских настройках.

Модели с геометрией помечаются в библиотеке, но нативный 3D-просмотрщик пока не реализован; PNG всегда показывается как 2D-текстура. Редакторы машин/рецептов, импорт `.jar` и просмотр геометрии `.nbt` также остаются отдельными этапами миграции и пока доступны только в старом веб-интерфейсе.

## Сборка для разработки

Требуется стабильный Rust и, для MSVC target на Windows, Visual Studio C++ Build Tools с Windows SDK. Сборка/запуск из checkout:

```powershell
cargo run -p factory-atlas-app
cargo build -p factory-atlas-app --release
```

Release-бинарник создаётся в `target/release/factory-atlas.exe`. В этой разработческой версии нет установщика и portable ZIP. Их нельзя объявлять готовыми, пока артефакт не упакован и не проверен на Windows.

## Runtime-зависимости GUI

Windows GUI использует только нативные зависимости eframe/egui, `winit`, `glow` и Windows native file dialogs (`rfd`). Для сборки `eframe` выключены web/WASM renderer features; `egui-winit` `links` feature выключен. В целевой Windows dependency tree не должно быть Tauri, Wry, WebView2 или browser launcher. Проверьте это командой:

```powershell
cargo tree -p factory-atlas-app --target x86_64-pc-windows-msvc -e normal
```

Старые `src/`, `src-tauri/`, `package.json`, Svelte, TypeScript, Vite и веб-проверки пока остаются необходимыми для существующей версии приложения. Удаление этих частей планируется отдельным этапом после проверки нативного GUI и переноса оставшихся пользовательских функций.
